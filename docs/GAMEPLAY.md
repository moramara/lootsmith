# ゲームのルール

プレイヤーから見たゲームのルールの正本です。コンテンツの追加手順やコード上の構造は [DEVELOPMENT.md](DEVELOPMENT.md)、
セーブデータの形式は [SAVE_FORMAT.md](SAVE_FORMAT.md) を参照してください。数値の実体は `src/core/content_tables.c` と
`src/core/simulation.h` の `BAL` にあり、この文書の表はその時点の値です。

## 目的

**30 日以内に 1500 ゴールドと評判 80 に到達する。** 所持金が -45 ゴールドを下回ると破産でゲームオーバーになります。
サンドボックス (クリア後の続行) では日数の上限も破産もありません。

## 基本の流れ

1 日は PREP (準備) → OPEN (営業) → SETTLE (精算) の順に進みます。

- **PREP**: 市場で素材を買い、クラフトし、在庫の価格を決め、アップグレードやギルド契約を扱う。
- **OPEN**: 店を開けると客が 1 人ずつ来る。提示した価格を受け入れるか断るかは客の予算・許容価格・装備の適合度 (FIT) で決まる。
- **SETTLE**: 売上、原価、維持費、評判の増減が精算され、翌日の市場価格が決まる。

## コンテンツ

- 素材: Iron、Wood、Mana、Copper、Steel、Silver、Obsidian (市場で買える 7 種)、Dragon Scale (市場では買えない希少素材。下の「Dragon Hunt」)
- 装備: Sword、Shield、Staff、Dagger、Spear、Grimoire (さらにギルドの設計図で Warhammer、Rune Bow、Crystal Orb、Wyrmcleaver)
- 客: Warrior (Sword)、Guardian (Shield)、Mage (Staff)、Thief (Sword)、Scout (Dagger)、Lancer (Spear)、Scholar (Grimoire)
  (設計図の装備を求める Knight、Ranger、Arcanist、Wyrm Hunter は、その設計図が解放されると現れる)
- アップグレード: Forge (鍛冶場)、Shop (店)、Supplier (仕入れ先)

客の種類は一様に抽選されるので、ある装備を一切作らない戦略は、その装備を求める客に対応できません。

## クラフト

クラフトは固定のルールで、データではありません。どの装備も **主素材 2 個 + 副素材 1 個** で作ります。装備の基本能力に、
2 つの素材の混合 `(2 * 主素材 + 副素材) / 3` を加え、Forge レベルで拡大します。価格は `BAL` の価値の式から決まります。
したがって、新しい素材や装備は自動的にほかのものと組み合わせられます。

## 装備の品質と特殊特性

クラフトした装備は **品質** を抽選し、上位 2 つの品質では **特殊特性** を 1 つ抽選します。どちらも個々の装備に付くので、
売却・納品・換金・保存をしても失われません。

| 品質 | 能力倍率 | 特性 |
|---|---:|---|
| Common | x1.00 | なし |
| Fine | x1.08 | なし |
| Masterwork | x1.18 | 1 つ |
| Legendary | x1.32 | 1 つ |

ATK / DEF / MAG / DUR は `最終値 = round(Forge 適用後の基本値 * 倍率 / 1000)` (整数、四捨五入) で、**WT は拡大されません**。
特性は倍率の後で加算されます。

| 特性 | Masterwork | Legendary |
|---|---|---|
| Keen / Warding / Arcane / Sturdy | ATK / DEF / MAG / DUR +2 | +3 |
| Lightweight | WT -1 | WT -2 (WT は 1 未満にならない) |

**確率** (パーセント、Common / Fine / Masterwork / Legendary) はギルドランクで決まります:
Apprentice 70/25/5/0、Journeyman 55/32/12/1、Master Craftsman 40/35/20/5、Grandmaster 25/35/28/12、Mythic Smith 20/33/30/17。
Forge の 1 レベルごとに 5 ポイントが Common から Fine へ移ります (Common の残りを超えては移らない)。
たとえば Apprentice + Forge 2 は 60/35/5/0 です。Apprentice は Legendary を引けません。

価値、推奨価格、FIT、売却の判定、ギルドの FIT 検査はすべて最終的な能力値を読みます。品質専用の価格式はありません。
換金は従来どおり *原価* の 50% で、品質は関与しません。

### Dragonforging (竜鱗鍛造): Dragon Scale の特殊特性

Dragon Scale (Dragon Hunt の報酬。[下記](#dragon-hunt-と-dragon-scale-mythic-smith-以降のエンドゲーム)) を使ってクラフトした
**Masterwork / Legendary** の装備には、通常の特性の代わりに、ドラゴン由来の特殊特性が付くことがあります。
Dragon Scale を温存して契約の報酬や価値の高い装備に回すか、特殊特性の抽選に賭けて使うかを選べます。

| 特性 | Masterwork | Legendary | 説明 |
|---|---|---|---|
| Draconic Edge | ATK +3 | ATK +4 | Dragon-forged edge: increased ATK. |
| Wyrmscale | DUR +3 | DUR +4 | Wyrm scales reinforce the item: increased DUR. |

- **抽選**: 品質が決まった後、Masterwork / Legendary のときだけ判定します (Common / Fine に特性は付かない)。
  使う Dragon Scale は、**主素材なら 2 個、副素材なら 1 個** (主・副の両方なら 3 個)。使用数が多いほど確率が上がります。

  | 使用する Dragon Scale | 特殊特性の確率 |
  |---:|---:|
  | 1 個 | 20% |
  | 2 個 | 30% |
  | 3 個 | 35% |

  当たったら Draconic Edge と Wyrmscale が 50% ずつ。外れたら、従来どおり通常特性 5 種類 (Keen / Warding / Arcane / Sturdy /
  Lightweight) から均等に 1 つ付きます。特殊特性は Masterwork / Legendary にだけ付き、**Dragon Scale を使わないクラフトには絶対に出ません**。
  判定の値 (確率表と候補) は `DRAGON_TRAIT_PCT` / `DRAGON_TRAIT_IDS` (`content_tables.c`) にあります。
- **効果の適用**: 通常の特性と同じ処理で、品質倍率の後に 1 回だけ加算されます。FIT・価値・推奨価格は特性を含んだ最終能力から求まります。
  上乗せは通常特性より +1 大きい程度なので、特殊特性は「希少素材の小さなボーナス」です (Dragon Scale 自体の価値の優遇は上の「希少度ボーナス」)。
- **表示**: 特性は在庫・納品・クラフト結果・客の画面に、通常の特性と同じ形式 (`TRAIT: DRACONIC EDGE (+4 ATK)`) で出ます。ヘルプ (F1) に仕組みの説明があります。

## ギルド契約

販売とは別の第 2 のループです。契約を受注し、求められた装備をクラフトして納品し、ゴールドと評判を得ます。
メイン画面の `GUILD [G]` から開きます (準備フェーズのみ。Esc / BACK で戻る)。

- **掲示板**: 毎朝 (とキャンペーン開始時) に 3 件 (`GUILD_OFFER_COUNT`) の契約が掲示され、なるべく 3 種類の別の客のものになる。
  誰も受けなかった契約はペナルティなしで翌朝に消え、空いた枠は同じ日には補充されない。
- **受注**: 準備フェーズ (キャンペーン中またはサンドボックス) に、同時に最大 2 件 (`GUILD_ACTIVE_MAX`)。
  期限日は `今日 + 日数 - 1` (受注日も数える) で、5 日目に受けた 3 日間の契約は 7 日目が期限。
- **納品**: 準備フェーズに、期限日を含めてそれまで。契約の客が求める装備で、かつ `equip_fit(客, アイテム) >= 最低 FIT`
  (客が使うのと同じ FIT) を満たすこと。アイテムは 1 つ消費される。
- **失効**: 期限日までに納品されなかった契約は、その日の精算で取り除かれる (通常の日の終わり、早期閉店、サンドボックスのいずれでも
  精算ごとに 1 回)。手数料も、ゴールドや評判の損失も、消費もない。
- **報酬** (納品時にのみ支払われる。評判には `BAL.rep_cap` の上限がある):

| 難易度 | FIT | ゴールド | 評判 | 日数 | 出現率 1〜5 日目 | 6〜15 日目 | 16 日目以降 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Easy     | 35+ | 35 | 1 | 3 | 70% | 30% | 15% |
| Standard | 50+ | 55 | 2 | 3 | 30% | 50% | 45% |
| Hard     | 65+ | 80 | 3 | 4 | 0%  | 20% | 40% |

- **会計**: ギルドのゴールドは別に集計され (精算画面に表示)、`revenue`・累計の売上・販売数には含まれない。損益 `net` =
  売上 + ギルドのゴールド - 原価 - 維持費 なので、累計の利益には含まれる。消費したアイテムの原価は、売れたアイテムと同様に原価に数える。
  納品の評判はその日の評判の増減に入る。
- Thief の Hard (FIT 65) 契約は、Forge レベル 0 では達成できない (Thief の最大 FIT は 63)。Forge レベル 1 から可能になる。
- 契約は解放済みの客に対してのみ掲示される。すでに掲示された掲示板は、ランクアップしても書き換えられない。受注中の契約は条件を
  保ち、新しい客は翌朝の掲示板から現れる。

## Dragon Hunt と Dragon Scale (Mythic Smith 以降のエンドゲーム)

Mythic Smith (`guild_done >= 50`) に到達した後も契約を続ける動機となる、特別なギルド契約と希少素材です。数値はすべて
`GUILD_DRAGON_HUNT` (`content_tables.c`) にあり、通常契約の報酬・難易度・出現率 (`GUILD_DIFFS` / `GUILD_SPAWN`) は変わりません。

| 項目 | 値 |
|---|---|
| 依頼主 / 必要装備 | Wyrm Hunter / Wyrmcleaver |
| 最低 FIT | 70 (通常の `equip_fit()` で判定する。専用の計算式はない) |
| 難易度 / 期限 | Hard / 3 日 (受注した日を数える。通常契約と同じ) |
| 報酬 | 170 ゴールド + 評判 4 + **Dragon Scale ×1** |
| 出現 | `guild_done >= 50` のときだけ、掲示板の更新ごとに 25% で **最大 1 件** |

- **掲示板**: Dragon Hunt が出ると、通常契約が 1 件減るので総数は常に 3 件。通常契約の依頼主は Dragon Hunt の依頼主 (Wyrm Hunter)
  と重ならない。出なかった日は従来どおり通常契約が 3 件 (Wyrm Hunter の通常契約も従来どおり出うる)。同時受注数 (2 件) も従来どおり。
  `guild_done < 50` では抽選をしないので、それまでの掲示板は新コンテンツの導入前と同一。抽選はギルドの乱数 (`guild_rng`) だけを使う。
- **画面**: 掲示板では `DRAGON HUNT` の札、Wyrmcleaver・最低 FIT・期限・ゴールド・評判・`+1 Dragon Scale` が見える。受注後は契約欄と
  納品パネルに残り日数が出る。納品に成功すると Dragon Scale の獲得がメッセージとバナーで通知される。
- **報酬の付与**: 納品が成功したときだけ付く。失効した契約や通常契約からは付かない。Dragon Scale の在庫が `BAL.stock_cap` (99) に
  達していて受け取れないときは、納品は拒否され (`GUILD_ERR_REWARD_FULL`)、装備・ゴールド・評判・契約・納品件数は何も変わらない
  (納品パネルに `DRAGON SCALE STOCK FULL!` と出る)。
- **Dragon Scale**: ATK 6 / DEF 5 / MAG 4 / DUR 8 / WT 3。市場画面には `HUNT ONLY` と表示され、購入ボタンを押しても
  `R_ERR_NOT_FOR_SALE` になるだけで在庫・所持金・価格は変わらない (価格は変動せず、市場更新で乱数も消費しない)。
  クラフトでは既存の規則どおり、主素材 (×2)・副素材 (×1) のどちらにも使える。混合・Forge・品質・特性・価値の計算に例外はない。
- **原価**: 報酬の Dragon Scale は **無料 (原価 0)**。受け取っても `mat_cost` は増えないので、Dragon Scale を使った装備の原価には
  その分が含まれない (ほかの素材と混ぜれば、その素材の原価だけが乗る。換金額も原価の 50% なので低い)。
- **希少度ボーナス (価値の式)**: Dragon Scale の能力値は Iron / Steel より ATK・DUR が低く、報酬は原価 0 なので、そのままでは装備の価値が
  下がってしまう。そこで素材テーブルの `rarity_value` (Dragon Scale は 18) を、使った素材 3 個 (主 2 + 副 1) 分、装備の価値へ直接加える:
  `価値 = 原価 * 0.6 + 能力スコア * 1.2 + (2 * 主素材の rarity_value + 副素材の rarity_value)`。推奨価格は価値 * 1.2 のまま。
  従来の素材は 0 なので、既存の装備の価値は変わらない。FIT は能力値だけで決まり、希少度は FIT に影響しない。
  Forge 0 の Wyrmcleaver (品質 Common) の価値は、Steel+Steel が 77、Scale+Scale が 106 (推奨価格 93 → 128)、
  Scale+Iron が 95、Iron+Scale が 81 (FIT は Steel+Steel 81、Scale+Scale 73)。

## ギルドランクと設計図

ランクは **納品済み契約数** (`guild_done`。失効したものは数えない) から導出されます。保存はされないので、納品数と食い違うことはなく、
ランクが下がることもありません。

| ランク | 納品済み契約数 | 解放されるもの (設計図 → 装備、その客) |
|---|---:|---|
| Apprentice | 0 | 出荷時のコンテンツ |
| Journeyman | 5 | Warhammer Plans → **Warhammer**、客 **Knight** |
| Master Craftsman | 15 | Rune Bow Plans → **Rune Bow**、客 **Ranger** |
| Grandmaster | 30 | Crystal Orb Plans → **Crystal Orb**、客 **Arcanist** |
| Mythic Smith | 50 | Wyrmcleaver Plans → **Wyrmcleaver**、客 **Wyrm Hunter**。クラフト品質の確率も向上する (最高ランク) |

- 未解放の装備はクラフトできない (UI では `LOCKED` と表示され、CRAFT は無効になる)。設計図が解放するのは装備の種類だけで、
  クラフトのルール (主 2 + 副 1)、能力値、Forge、価格の式は通常どおり。
- 未解放の客は現れない。何も解放されていない間の客の抽選は、設計図導入前と同じ 7 タイプに対する同じ 1 回の抽選なので、
  契約を一度も納品しないプレイヤーは従来とまったく同じ客と市場を見る。既存の客の行列は、ランクアップでは作り直されない
  (納品は準備フェーズにしか起きず、次の開店から新しいランクが使われる)。
- ギルド画面には `RANK`、`CONTRACTS: n / 次のランクまで` (または `MAX RANK`)、次の設計図が表示される。`BLUEPRINTS [B]` は
  (ページ送りのある) 設計図の一覧を開き、未解放のものも見える。ランクが上がる納品では、バナー (`GUILD RANK UP!` +
  `BLUEPRINT UNLOCKED`) が一度だけ表示される (納品の前後でランクを比べて決め、保存はしない)。

新しい装備と客 (優先度の重みの合計は 100):

| 装備 | ATK | DEF | MAG | DUR | WT | 客 | 予算 | 必要 FIT | 優先度 |
|---|---:|---:|---:|---:|---:|---|---:|---:|---|
| Warhammer | 13 | 3 | 0 | 8 | 7 | Knight | 100-180 | 40-68 | ATK 40, DEF 30, DUR 30 |
| Rune Bow | 10 | 1 | 3 | 5 | 3 | Ranger | 80-155 | 40-65 | ATK 50, 軽さ 50 |
| Crystal Orb | 0 | 2 | 14 | 4 | 2 | Arcanist | 100-200 | 40-70 | MAG 70, DUR 30 |
| Wyrmcleaver | 14 | 2 | 1 | 9 | 5 | Wyrm Hunter | 120-210 | 50-75 | ATK 45, DUR 35, 軽さ 20 |

## オプション画面と効果音

**音声。** ループする BGM (`assets/audio/bgm_hearth.ogg`、80 秒、シームレス) はゲーム開始時に一度だけ再生を始め、画面遷移では
再開されません。BGM と効果音は別々の音量を持ち、0 % はその群だけを無音にします。音声はすべてオリジナルで、由来は
[assets/audio/README.md](../assets/audio/README.md) にあります。オーディオデバイスを開けない場合やファイルがない場合は、ゲームは
無音で起動・動作します (OPTIONS 画面がそれを表示します)。

**OPTIONS 画面。** タイトル画面 (`OPTIONS [F2]`)、ゲーム中のすべての画面 (ヘッダのボタン。日報/クリア/ゲームオーバー画面では隅のボタン)、
またはどこでも **F2** で開きます。BGM と SE の 2 本のスライダー (0〜100 %、数値表示) があり、0 % では赤い `MUTE` が出ます。

- マウス: スライダーのクリック/ドラッグ、行の上でのホイール
- キーボード: 上下で行を選択、左右で ±5 (Shift で ±1)、Home / End で 0 % / 100 %、BACK で Enter、Esc または F2 で閉じる
- 開く前の画面は記憶されているので、BACK でタイトルまたは元のゲーム画面へ正確に戻る
- 音量は再生中の BGM とすべての効果音に即座に反映される。SE スライダーを離す (またはキーで動かす) と、音量を確かめる小さなチック音が鳴る
- 既定値: BGM 35 %、SE 65 %

設定ファイルの形式と書き込みのタイミングは [SAVE_FORMAT.md](SAVE_FORMAT.md) にあります。

**どの音がいつ鳴るか。** UI は 1 フレームの間に、イベントが要求した音を集め、優先度が最も高い 1 つだけを再生します。
したがって 1 回の入力で 2 つの音が鳴ることはありません (例: BUY はチック + コイン → コインのみ)。

| イベント | 音 |
|---|---|
| 有効なボタン / ショートカット | `ui_click`。1〜5 のタブは `ui_nav`。BACK、Esc、OPTIONS を閉じるのは `ui_back` |
| ホバー、無効または灰色のボタン | 鳴らない |
| あらゆる失敗メッセージ (ゴールド/素材不足、未解放、保管が満杯、客の拒否・退場、フェーズに合わない画面など) | `error` |
| 素材の購入、在庫の換金 | `coin` |
| 店のアップグレードの購入 | `upgrade` |
| クラフト | `craft`。Masterwork / Legendary は `craft_rare` |
| 開店 / 翌日または新キャンペーン | `shop_open` / `day_start` |
| 客に売れた | `sell` |
| ギルド契約の納品 / ランクが上がる納品 (前者の代わりに鳴る) | `contract` / `rank_up` |
| CAMPAIGN CLEAR / GAME OVER 画面に入る | `clear` / `gameover` |


## BOT の自動プレイを観戦する

タイトル画面の `WATCH BOT [B]` を選ぶと、通常キャンペーンとは独立した BOT のプレイを観戦できます。BOT は在庫の仕入れ・製作・設備強化・採算の取れるギルド契約・客への販売を行い、画面右側に直近の行動を表示します。BOT の進行は通常のセーブファイルへ保存されません。

- `SPACE`: 一時停止 / 再開
- `RIGHT`: 一時停止中に 1 段階進める
- `-` / `=`: 進行速度を変更する
- `R`: キャンペーン終了後に同じシードで再実行する
- `ESC`: タイトル画面へ戻る

BOT は Dragon Hunt も同じ公開 API (`guild_accept` / `guild_deliver`) で扱います。最低 FIT を満たすレシピが作れる契約だけを受注し、
Dragon Scale の在庫枠がない (受け取れない) 契約は受注も納品もしません。市場で買えない素材は仕入れの候補にせず、報酬の素材も使いません。
報酬の素材の価値は採算に含めていません (保守的な評価)。

同一シードでは BOT の判断とシミュレーション結果が再現されます。戦略はデモ用のヒューリスティックであり、常にキャンペーンをクリアする保証はありません。
